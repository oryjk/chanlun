# 缠观原生 iOS 与 iPadOS 首版设计

设计已由用户确认。用户随后明确本机无 Xcode，授权先编写代码并提交，之后在 Mac 继续编译、签名和 TestFlight 验证。

## 目标与已确认范围

将现有缠观 H5 功能复刻到原生 App，覆盖 iPhone 和 iPad，共用现有 Python 后端，先通过 TestFlight 供少量用户内测。用户已有 Apple 开发者账号。

用户已确认采用 SwiftUI 页面与 UIKit 原生图表的组合。首版使用 Sign in with Apple，微信登录和账号关联后续再讨论。行情继续支持游客访问。

用户提到未来可能在 K 线上加入社交，但尚无功能设想。此信息仅影响组件边界与扩展能力，不构成首版社交需求，不设计或实现评论、动态、好友、内容分发和审核系统。

## 技术路线与取舍

| 路线 | 取舍 | 决定 |
| --- | --- | --- |
| SwiftUI 页面与 UIKit 原生图表 | 页面适配与状态表达采用 SwiftUI；图表使用 UIKit 绘制与手势处理，精细控制复杂叠加图层；增加一处框架桥接 | 用户已选择 |
| 全 SwiftUI 与 Canvas 图表 | 技术栈统一，但复杂手势、命中检测和图表元素的无障碍需要额外处理 | 未选择 |
| App 内嵌现有 H5 | 可复用现有页面与 ECharts，但不符合本次原生界面与交互的方向 | 不采用 |

Apple 支持通过 UIViewRepresentable 将 UIKit 视图集成到 SwiftUI；NavigationSplitView 可根据可用空间在多列与单列之间适配。[UIKit 集成](https://developer.apple.com/tutorials/swiftui/interfacing-with-uikit)、[导航适配](https://developer.apple.com/documentation/technotes/tn3154-adopting-swiftui-navigation-split-view)。

### 实现默认值

以下为设计方提出的默认选择，尚未由用户逐项指定：

- 最低版本为 iOS 17 和 iPadOS 17；实施前核对内测设备，若需要更低版本则调整。
- iOS 源码放入同一仓库的 `ios/`，一个 App target 同时支持 iPhone 和 iPad。
- 图表先以 UIKit 与系统绘图能力实现，避免引入依赖 ECharts、WebView 或固定业务模型的图表引擎；具体采用 Core Graphics 或图层组合由实现者决定。
- 以现有简体中文文案、白底、墨蓝主色及红涨绿跌语义为基线；首版优先明亮外观。
- 首版只保持一个当前证券和一个当前周期，不新增多证券同屏和多个独立窗口。

| 模块 | 首版行为 |

| 图表交互 | 水平拖动、双指缩放、长按十字光标，展示对应 K 线、MACD 与信号详情；缩放和刷新保持合理视窗 |
| 结构解读 | 走势类型、背驰、买卖点、质量证据、失效参考和多级别结构印证 |

当前 H5 的收藏和跟踪只有登录引导，没有实际功能，首版不据此新增这些业务。品牌与加载动效保留相同用途，原生实现可采用原生矢量动画，不要求逐帧一致。

### 分析语义与市场范围

- 缠论、MACD、买卖点、失效核查与榜单分组继续以服务端结果为准。客户端不再独立实现缠论算法。
- 候选不能展示为已确认机会；历史已知收盘越界后不复活；结构端点日期不等于首次识别或确认日期；未知字段保持未知。
- H5 领域层仍有结构结论文案、搜索筛选、价格格式与端点涨跌计算。首版在 Swift 领域层实现等价规则，并用同一批 JSON 样例验证两端输出；不为首版批量修改现有行情 API。
- 股票价格两位小数、ETF 三位，时间和交易时段依据市场时区，榜单更新时间明确使用北京时间，避免设备所在时区改变日期含义。
- 市场范围与届时 H5 和后端的有效能力对齐，不把证券搜索可返回某市场视为其四周期分析和主备源均受支持。
- 证券标识迁移已有独立计划。iOS 将 `secid` 作为不透明标识，经边界转换后使用，不在组件或图表中解析东方财富市场号。首版联调固定一份实际 API 契约；标识迁移是否已完成不作为本设计的先决条件，不在 iOS 工作中顺带实施该迁移。
- 保留“不构成买卖建议”提示。

## 原生架构与扩展边界

依赖方向遵守项目整洁架构：`Presentation -> Application -> Domain`，`Infrastructure` 实现 Application 的端口，`App` 是唯一组合根。UIKit、SwiftUI、URLSession、Apple 登录 SDK 和 Keychain 不进入领域层。

| 层 | 职责 |
| --- | --- |
| Domain | 不可变行情与信号对象、周期、价格与时间规则、结构结论选择器、图表坐标和值模型 |
| Application | 搜索、快照、报价、榜单、联立等 Query；报价采样、Apple 登录、退出和删除账号等 Command；声明读写与身份端口 |
| Infrastructure | URLSession 请求、明确 DTO 映射、Apple 授权适配、Keychain、必要的本地状态存储 |
| Presentation | SwiftUI 页面与交互状态、UIKit 图表及 SwiftUI 桥接、请求生命周期与布局适配 |
| App | 创建适配器和用例并注入页面；环境和服务地址配置 |

### 图表

渲染器接收明确的绘图数据，不直接请求网络、读会话或判断社交规则。坐标变换、视窗、命中检测、绘制及交互事件分别封装，主图、成交量和 MACD 共用时间定位。

为未来可能的用户内容保留一般性的覆盖层与交互扩展位置，绘图结果可以向外返回证券、周期、时间与价格位置。首版不增加社交专用数据类型、表、API 或插件系统。

K 线数组索引、笔 ID 和中枢 ID 都可能随行情窗口与重算变化，不作为未来用户内容的长期主键。跨快照的定位还会受复权、数据修订和跨周期聚合影响；这些问题在具体内容需求形成后再定规则，首版不宣称已解决社交锚定。

## iPhone 与 iPad

iPhone 采用紧凑导航和单列内容。iPad 宽窗口利用多列组织列表与证券详情，图表和结构解读优先获得更多空间；窄窗口折叠为单列。

适配依据实际窗口宽度，覆盖横竖屏、分屏与窗口尺寸变化，避免仅按设备型号判断。导航、当前证券和周期使用共同状态；尺寸变化不重置当前证券或重复启动轮询。首版具体布局与间距留给界面设计确认，以上不构成已确认视觉稿。

## Apple 登录与后端扩展

现有 H5 身份直接来自报名系统，`UserIdentity.user_id` 为其整数 ID，且会话从 Cookie 读取。新增 Apple 登录需要独立的账号映射与原生会话能力，不能把 Apple 用户标识直接塞入现有整数 ID。

### 账号与持久化

- 新增 App 内部用户标识与外部身份映射，Apple 身份以验证后的 issuer 和 subject 关联；内部用户 ID 采用不透明 UUID，避免与报名系统整数 ID 混用。
- Apple 账号首版独立于报名系统账号，不依据邮箱自动合并，也不实现微信绑定；原 H5 登录和响应保持兼容。
- 新增明确的账号 Reader、账号 Writer、Apple 验证 Gateway 与原生会话 Reader/Writer，Query 不产生写入。
- 少量内测默认使用独立 SQLite 账号存储，使用原子事务处理身份映射唯一性、会话状态和删除；账号数据与榜单运行库分离，不写入 Git。
- 私钥、Apple 刷新令牌及会话凭证不进入日志和源码；需要保留以执行令牌撤销的 Apple 凭证在服务端加密保存，密钥通过部署配置注入。

### 登录与会话

1. 服务端签发短时、单次使用的登录挑战，客户端发起原生 Apple 授权并关联 nonce。
2. 客户端将 identity token、authorization code 和挑战标识提交后端。服务器验证签名、issuer、audience、expiry 和 nonce，并校验挑战有效性及使用状态。
3. 服务端兑换授权 code，建立或读取内部账号并签发 App 会话；原生接口使用独立命名空间，具体路径由实现计划确定。
4. 原生会话采用随机不透明 Bearer token，服务端只保存摘要、用户、到期和撤销状态，客户端保存在 Keychain。首版有效期默认 30 天，到期重新执行 Apple 登录，不另建会话刷新协议。
5. 原 H5 HttpOnly Cookie 会话维持原路径。新增会话接口显式区分身份来源，避免数字 ID 与 UUID 混用。
6. 退出登录立即撤销该 App 会话并清理本地状态；凭证撤销或账号删除后，后端拒绝该账号会话，客户端回到游客态。

姓名和邮箱按可选资料处理，使用 subject 识别账号。Apple 姓名可能仅首次授权返回；缺失时使用默认名称，不要求补手机号。[身份验证](https://developer.apple.com/documentation/signinwithapple/verifying-a-user)、[获取身份](https://developer.apple.com/documentation/signinwithapple/receiving-a-users-identity-token)。

账号页提供删除入口，删除内部账号、映射与会话，并调用 Apple 的撤销接口。撤销遇到可重试网络错误时持久化最小待处理状态，先禁止访问账号，再重试撤销并清理剩余凭证；操作对重复请求保持幂等。Apple 凭证状态检查与服务端通知配合处理用户在系统中撤销授权的情况。[删除要求](https://developer.apple.com/support/offering-account-deletion-in-your-app/)、[账号变更](https://developer.apple.com/documentation/signinwithapple/processing-changes-for-sign-in-with-apple-accounts)。

## 网络与性能

保留 Python。当前每次分析约 240 根 K 线，少量内测无需语言迁移、分布式缓存或全市场实时计算。API 与后台榜单现有部署方式可继续验证，不借 iOS 首版实施全套性能重构。

- 实时页面前台且处于交易时段时默认每 3 秒读取报价；同一证券只允许一轮报价与采样请求执行。进入实时页先读取已有分时序列，随后按现有 Command 提交采样。
- 榜单可见时默认每 60 秒读取持久化结果；手动刷新不触发榜单重算。
- 隐藏页面和进入后台时停止轮询，取消未完成请求；恢复前台时重新判断交易时段并立即读取，避免只在页面首次打开时决定是否启动轮询。
- 搜索防抖、切证券时取消旧请求，迟到响应不得覆盖新证券；失败保留可用数据并标记更新时间，重试采用有限退避。
- 客户端共享当前证券的在途请求，避免图表与联立重复发起完全相同的调用；后端如需跨请求合并取数，作为独立的小优化验证。
- 现有报价 JSON 存储只有进程内锁；首版不直接通过增加 API 进程数量扩容，未来扩容先替换或协调文件写入。

## 验证与 TestFlight 交付

### 行为与架构

- 共享样例覆盖行情 DTO、ETF 精度、周期日期、候选与确认、历史失效不复活、旧榜单缺字段、联立部分级别失败、首次准备与空榜。
- 原生领域与用例单元测试验证边界规则；架构检查防止 UI 直接请求网络、SDK 进入核心层和 Query 执行业务写入。
- 图表验证同根 K 线的主图、量与 MACD 光标一致，缩放与拖动后结构定位正确，标签不会被遮挡。
- H5 与 iOS 使用相同后端与固定样例核对结构结论，避免实时行情变化掩盖差异。

### 真机与服务

- iPhone 和 iPad 真机检查行情、搜索、图层、分时、榜单、账号及错误恢复；覆盖横竖屏、iPad 分屏、前后台切换与断网恢复。
- Apple 登录至少验证首次授权、再次登录无姓名、用户取消、挑战重放、错误 audience、到期凭证、退出、删除和撤销授权。
- 修改后端时按 AGENTS.md 执行 Python 测试、前端测试与构建，以及真实 HTTP 回归，包含原 H5 登录；测试使用隔离账号与临时持久化目录。
- 在实际内测服务器检查少量并发用户下的接口延迟、错误率和榜单构建期间的看盘体验，不把本机合成计算耗时当作容量承诺。

### 发布前配置

需要可用的 Mac 与 Xcode、开发团队与 Bundle ID、Sign in with Apple capability、服务端 Apple key 与 client 配置、稳定 HTTPS API 地址及 App Store Connect 的 App 记录。开发者账号存在不代表这些配置已就绪，实施时逐项检查现有环境，密钥通过安全配置提供。

提供可复现的构建与归档说明，完成签名、上传和实际安装验证后才称为 TestFlight 可用。选择内部或外部测试组属于交付配置，不改变首版功能；相关发布操作执行时遵守用户授权，不在设计阶段上传或提交。

## 实施顺序与后续边界

先确认本设计，再制定实施计划。建议顺序为固定实际 API 契约和样例、建立原生分层与导航、完成原生图表及分析页、补齐分时与榜单、实现 Apple 账号闭环，最后进行双端回归和 TestFlight 配置。

现有架构边界重构可能与本工作并行。实施前重新读取 AGENTS.md、HEAD 与工作区，以当时的端口和组合入口为准；不覆盖或回退其他正在进行的改动。

社交、微信账号关联、收藏跟踪、多证券同屏、离线完整分析、盘中全市场推送和商业化都需要新的明确需求。本次只保留自然的组件边界，不为这些方向预建平台。
